The reusable workflows live in `.claude/skills/` — see
[`.claude/skills/SKILLS.md`](.claude/skills/SKILLS.md) for the catalog and
[`.claude/skills/AUTHORING.md`](.claude/skills/AUTHORING.md) for what a good one looks like. Each
skill directory holds its definition plus its executable backend. Agents that cannot invoke skills
natively can still read the `SKILL.md` and run the backend directly — the scripts have no
dependency on any particular agent harness.

## The three things most likely to trip you up

**Nothing real goes into this repository.** No real receipt, statement, account number, merchant,
person, hostname, credential or dollar figure — not in a fixture, a test, a doc, a skill, a
screenshot or a commit message. Fixtures are generated by `scripts/gen_fixtures.py`; demo data by
`scripts/gen_demo_data.py`. Run output (`logs/`, `data/`, `.playwright-mcp/`, skill `runs/` and
`reports/`) is gitignored because it is a dump of whatever books the app was showing.

**Engine correctness is never traded for speed, cost or a green gate.** Flag an uncertain match
for review rather than guess it, never sum across currencies, and when a test catches a miss fix
the engine, not the test. `pytest.ini`'s exclusion list only ever shrinks.

**There is no CI.** The real pre-merge gates are local and `./scripts/gates.sh` runs all four
(ruff, pytest, web typecheck, web build). A running server keeps serving the code and the
`web/dist` bundle it started with: rebuild and restart before claiming a change works.
